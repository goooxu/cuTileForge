# 第十六阶段：修好了速度奖励的死区，但训练分布选错了

**结论先说**：找到并修掉了一个真实的缺陷——速度奖励在 1.0x 以下完全没有梯度，而基准的
中位就是 0.92x。但这一轮**没有让 kernel 变快**：在两个模型都解出的 136 道题上，
逐题速度比的中位是 **1.000x**。

**M（150/200）仍然是最好的模型。**

## 1. 死区是真的

```python
def speed_bonus(speedup) -> float:
    if not speedup or speedup <= 1.0:
        return 0.0          # <-- 0.1x 和 0.99x 同分
```

**1.0x 以下一律返回 0。** 而 dev 上最好模型的中位加速比对 `torch.compile` 是 0.92x——
死区正好盖住了几乎所有基准 kernel 所在的区间。十五轮 RL 里，速度这个维度在最需要梯度的
地方**根本没有梯度**，分不出慢十倍和慢 1%。

改成在对数空间对称分级（0.25x 及以下 −0.3，1.0x 为 0，4x 及以上 +0.3），pass 的分数区间
变成 0.70–1.30，**永远高于失败的上限 0.60**，所以正确性仍然绝对优先。这个修复本身是对的，
应该保留。

## 2. frontier 换成"稳定解出"的题

`select_frontier.py` 加了 `--mode solid`：只留通过率 100% 的题。逻辑是这批题上正确性在
组内是常数、贡献零 advantage，速度项自动承担全部梯度。这正是默认模式当作"无梯度"扔掉的
那批（level 89 有 326 道、level 86 有 189 道），配额后 301 道。rollout 温度提到 1.2
（第十五阶段的判定实验正是在这个温度下才显出变异）。

## 3. 结果：表面上涨了，实际没有

| | pass@1 | pass@4 | 解出 | 快过 compile | 中位 |
| --- | ---: | ---: | ---: | ---: | ---: |
| M | 51.6% | **75.0%** | **150/200** | 43 | 0.92x |
| O | 52.4% | 73.5% | 147/200 | **46** | **0.94x** |

看起来速度涨了（43 → 46、0.92x → 0.94x）。但 O 和 M 解出的题不是同一批，中位是在不同
人群上算的。**在两者都解出的 136 道题上逐题对比**：

| | |
| --- | --- |
| 逐题 O/M 速度比的中位 | **1.000x** |
| 变化在 ±5% 以内的题 | **120 / 136** |
| O 更快 / 更慢 | 10 / 6 |

**kernel 根本没变快。** 表面那点涨幅是解出题目集合变化带来的构成效应。

## 4. 为什么没用：训练分布的速度区间和基准对不上

训练日志里 `fast_rate` 的中位是 **0.70**——七成的 rollout 已经快过参考实现。
而 dev 上只有 46/200（23%）。第十五阶段的判定实验也显示，那些合成题上模型能拿到
**6-11x** 的加速。

**也就是说：训练是在"已经赢很多"的区间里教模型"赢得更多"，而基准的困难在
"0.92x，打不过 cuBLAS 和 inductor"这个区间。** 从 6x 学到 11x，对如何把一个卷积从
0.92x 推到 1.0x 没有任何帮助。

### 一个流程错误

建 frontier 时用的两次采集（`tail_k8`、`Hfrontier_k8`）跑的是 `fast_verify.py`
**不带 `--measure-time`**，所以 verified.jsonl 里一条计时都没有。我筛 frontier 时
**只看了通过率，对这批题的速度区间完全没有信息**——事后回头查才发现 frontier 里
"有计时的题：0"。

选一个以速度为目标的训练集，却对它的速度分布一无所知。这个错误应该在筛之前就被发现，
只要看一眼 frontier 的 speedup 分布就行。

## 5. 下一步

修法很直接：**speed frontier 应该按"模型稳定解出、但比参考慢"来筛**，也就是
`0 < speedup < 1.0` 的那批，这才是基准所处的区间。这需要采集时带 `--measure-time`
（成本是两阶段计时，只对通过的候选跑，可以接受）。

其余保留：死区的修复、solid 模式、温度 1.2 都是对的，错的只是筛选条件缺了速度这一维。

## 6. 已知的边界

- pass@4 从 75.0% 掉到 73.5%、解出 150 → 147，速度目标是有代价的。
- KL 末段 0.025，比前几轮高一个量级，但远低于第十一阶段失控的 0.55。
- 正确性没被带崩（训练侧 pass 0.977、纯度 0.993），这是设计时最担心的，防住了。
