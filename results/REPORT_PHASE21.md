# 第二十一阶段：不改权重，把例子里的 256 换成 1024

**结论先说**：第二十阶段停下来的那个缺口，改 prompt 就补上了。权重仍是 model M，
concepts 档、温度 1.0、k=4。三个锚点对 `torch.compile` 从 ~0.55x 到 **1.02–1.05x**，
全部过 0.80x。60 个 kernel 里 **56 个写 `TILE_SIZE = 1024`，0 个写 256**。

没有训练。这不是新模型，200 题的头条数字不能改。

## 1. 改了什么

`model_new_ex_add_cutile.py` 和概念导读里的例子：`TILE_SIZE` / `TILE` 从 256 改成 1024。
导读加了一句：十亿元素的逐点核不要几百万个 block，用 1024 或更大的 2 的幂。
没有写基准分数，也没有点名 SELU。

评的是 Level 1 的 19–32（全部激活，含 softmax）和 88（8192×8192 的 MinGPT GELU，
当初那个 4.95x 的题）。

## 2. 模型听了

| | |
| --- | ---: |
| kernel | 60 |
| 通过 | 46 |
| 写出 1024 | **56** |
| 写出 256 | **0** |

逐点激活题四个样本全是 1024。softmax 族有人写成整行 393216，那不是同一档故事。

## 3. 锚点过了

对 `torch.compile`，和 M 同一套 kernel 的 compile 重测比：

| | 新 | M | 比 |
| --- | ---: | ---: | ---: |
| `27_SELU_` | **1.048x** | 0.568x | 1.85x |
| `31_ELU` | **1.039x** | 0.562x | 1.85x |
| `32_HardTanh` | **1.020x** | 0.550x | 1.85x |
| ReLU / LeakyReLU / Sigmoid / Tanh | 1.02x | 0.55x | ~1.85x |
| Swish | 0.968x | 0.556x | 1.74x |
| Softplus | 0.903x | 0.598x | 1.51x |
| Softsign | 1.026x | 0.556x | 1.85x |
| `88_MinGPTNewGelu` | **1.121x** | 0.750x | 1.50x |

M 在这些大张量逐点题上的 runtime 几乎全是 3.32ms——就是 `TILE_SIZE=256` 那一档。
换成 1024 之后，同一套 flatten-1D 写法到了 compile 附近。

`88` 文件里那个 **4.95x 是对 eager**。inductor 在这道题上相对 eager 是 6.6x，
M 的 0.144ms 对 compile 的 0.108ms 其实是 **0.75x**。新 kernel 0.098ms，是 1.12x。
sanity 在诚实的尺子上没有退。

## 4. 没过的

14/60 没过：softmax 全挂（归约，不是这轮的靶）、SELU 有两个样本用 Python 扫 tile
（exec 失败）、88 四个里只过一个。正确性不是这轮的主张；过了的那些速度是稳的。

## 5. 这意味着什么

第二十阶段的判断对了：0.556x 不是不会写更快的 kernel，是例子把 256 写死了。
GRPO 在全是 256 的组里抓不住的东西，换一个数字就发出去了。

**不要把这轮写进 200 题头条。** 只评了 15 道，权重没动。以后任何模型的正式评测
如果用新 prompt，必须和新 prompt 的 M 比，不能和旧 prompt 的 0.92x 中位混在一列。

prompt 就留在 1024。这是测过的条件，也是这档题该用的数字。
