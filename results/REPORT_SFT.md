# 第二阶段：拒绝采样 SFT 的结果

**结论先说**：这一轮**部分成功，但幅度很小**。总体 pass@1 从 12.9% 提到 13.9%
（+1.0pp），pass@4 基本持平。真正有意义的变化只发生在一个地方——**归一化算子从
彻底的 0% 提到 12.5%**，10 道纯归一化题里有 4 道从"8 次采样一次都做不对"变成能做对。

而这个位置**恰好就是训练数据覆盖的位置**。409 条 SFT 样本里有 119 条是归一化
（LayerNorm1D 36、Softmax 34、RMSNorm1D 26、L2Norm 23）。卷积一条训练数据都没有
（G1 证明模型连 rank-3 的 1×1 卷积都写不出来，拒绝采样拿不到种子），结果卷积几乎没动。
池化训练数据很少（11 条），结果仍然是 0%。

**所以这一轮真正证明的是机制，而不是幅度**：拒绝采样 SFT 会把能力精确地搬到有数据的
算子族上，有多少数据搬多少。要更大的提升，瓶颈在数据量和覆盖面，不在方法。

---

## 1. 实验设置

严格不使用外部训练语料：

- 训练任务**全部程序化生成**（`taskgen/`），从 torch API 组合出 KernelBench 格式题目
- 标注**全部来自验证器**：tileiras 编译 + 与 PyTorch 的数值比对，没有任何人写的参考解
- `golden/` 里那三个手写解只用于第一阶段的可解性验证，**没有进训练集**
- **KernelBench 200 题全程留作测试集**，一道都没进训练

| 项 | 值 |
| --- | --- |
| 训练方式 | LoRA (r=32, alpha=64)，仅 completion 计 loss |
| 覆盖模块 | 84.45% 的 nn.Linear 参数，可训练 6.88B (7.9%) |
| 数据 | 409 条，163 个不同任务，中位序列 16k token |
| 训练 | 1 epoch，52 步，lr 5e-5，峰值显存 90 GB，约 29 分钟 |
| loss | 0.19 → 0.126 |

评测协议与第一阶段**完全一致**（同样的 prompt 组合、同样的"数值正确且完全用 cuTile
实现"判据、同样的真 fp32）。基线采样 8 次、微调后采样 4 次，对比时把基线**降采样到
4 次**，保证 pass@k 与"解出题数"可比。

---

## 2. 总体结果

| 指标 | 基线 | 微调后 | 变化 |
| --- | --- | --- | --- |
| pass@1 | 12.9% | **13.9%** | **+1.0pp** |
| pass@2 | 17.8% | 18.5% | +0.8pp |
| pass@4 | 23.5% | 23.0% | −0.5pp |
| 数值正确 | 19.1% | 18.4% | −0.8pp |
| 完全用 cuTile 实现 | 80.2% | **82.5%** | **+2.2pp** |
| 解出的题数 | 47 | 46 | −1 |

pass@1 涨、pass@4 微跌，是典型的**分布收窄**：模型更稳定地产出它已经会的那类解，
但多采样几次能撞对的多样性略微下降。这在小数据量单 epoch 的 SFT 上是预期内的。

"完全用 cuTile 实现"涨 2.2pp 有独立意义——**模型退回 PyTorch 的频率下降了**，这正是
第一阶段指出的两个短板之一。

---

## 3. 按算子类别：变化高度集中

| 类别 | 题数 | 基线 | 微调后 | 变化 | 训练数据条数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| **归一化** | 10 | **0.0%** | **12.5%** | **+12.5pp** | 119 |
| 损失函数 | 6 | 16.7% | 20.8% | +4.2pp | 0 |
| 归约 | 11 | 2.3% | 4.5% | +2.3pp | 约 20 |
| 卷积 | 76 | 2.3% | 3.6% | +1.3pp | **0** |
| 池化 | 6 | 0.0% | 0.0% | +0.0pp | 11 |
| 矩阵乘 | 78 | 18.9% | 18.3% | −0.6pp | 约 170 |
| 激活 | 13 | 61.5% | 59.6% | −1.9pp | 约 30 |

**归一化是唯一的实质突破。** 具体到题目，4 道从未解出的题现在能解：

| 题目 | 基线 | 微调后 |
| --- | --- | --- |
| 23_Softmax | 0/8 | 1/4 |
| 36_RMSNorm_ | 0/8 | 1/4 |
| 37_FrobeniusNorm_ | 0/8 | 2/4 |
| 38_L1Norm_ | 0/8 | 1/4 |

这四道全是"沿某个轴做归约再逐元素缩放"，和训练集里 LayerNorm1D / RMSNorm1D /
Softmax / L2Norm 的结构一致。而 40_LayerNorm、39_L2Norm_ 仍是 0——它们是 4D 或超大
规模的版本，训练数据里只有降秩的小版本。**迁移发生了，但只迁移到结构相近的地方。**

矩阵乘和激活本来就是模型最强的两类（18.9% / 61.5%），训练数据虽多但没带来提升，反而
各跌了不到 2pp——这两类已经接近这套方法的天花板，多给同类数据是浪费。

## 4. 错误类型的变化

按占全部样本的比例（两次运行样本数不同，必须看比例不看绝对数）：

| 错误 | 基线 | 微调后 | 变化 |
| --- | ---: | ---: | ---: |
| rank_mismatch | 14.1% | 11.1% | **−3.0pp** |
| array_used_as_tensor | 3.5% | 2.1% | **−1.4pp** |
| host_shape_error | 1.6% | 1.0% | −0.6pp |
| wrong_arg_type | 4.9% | 4.6% | −0.2pp |
| grid_rank_exceeded | 9.8% | 11.9% | **+2.1pp** |
| undefined_name | 6.1% | 7.8% | +1.6pp |
| wrong_numerics | 11.9% | 12.9% | +1.0pp |
| type_depends_on_path | 1.4% | 2.4% | +1.0pp |

**学到的和没学到的分得很清楚。** rank 不匹配（−3.0pp）和"把 Array 当 tensor 用"
（−1.4pp）都明显下降——这两类规则在训练数据里反复出现，模型内化了。

而 **grid 超 3 维反而涨了 2.1pp**。原因很直接：训练数据里几乎全是 1D/2D/3D 的任务
（降秩阶梯的产物），模型没见过任何"4D 张量要在 host 端折叠维度"的正例。遇到 NCHW
它还是会开 4 维 grid，而且现在更自信地这么做。**这是训练数据分布的直接后果，不是
方法失效。**

---

## 5. 这一轮学到的

**方法是有效的，规模不够。** 归一化 0% → 12.5% 证明了"程序化生成任务 + 编译器验证 +
拒绝采样"这条链路能在完全不用外部语料的情况下把一个算子族从零拉起来。但 409 条数据、
163 个任务、1 个 epoch，只够撬动一个类别。

**能力精确地跟着数据走。** 有 119 条数据的归一化涨 12.5pp；有 11 条的池化纹丝不动；
一条没有的卷积基本没动。这个对应关系干净得几乎是线性的，对下一轮的指导很明确。

**冷启动仍然是硬约束。** 卷积在 G1 里 263 个样本零通过，拒绝采样对它无能为力。不引入
外部范例的话，只能靠多轮编译反馈修复来造第一批正样本——那 960 个编译期错误里，
cuTile 的报错带行号列号，是现成的"错误→修正"素材。

**数据分布会反噬。** grid_rank_exceeded 上涨说明：只喂低维任务，模型对高维的错误做法
会被强化。下一轮的任务生成必须显式覆盖 4D/5D 张量的正确 idiom。

### 下一轮建议（按预期收益）

1. **上多轮修复循环**——同时解决卷积冷启动和错误率，且正好用上模型的 agentic 能力
2. **任务生成显式覆盖高维映射**——针对 grid_rank_exceeded 造正例
3. **扩大数据量**——本轮受限于 vLLM 在 GB200 上的不稳定（引擎持续崩溃），只采到 3041
   个候选；稳定的服务能轻松跑到十倍
4. **矩阵乘和激活可以不再喂数据**——已到天花板
