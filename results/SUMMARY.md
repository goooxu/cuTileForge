# 二十轮之后：结果、没做到的事、以及方法学教训

这份是全项目的汇总。逐阶段的细节在 `REPORT_PHASE*.md`，过程流水在 `docs/WORKLOG.md`。

## 1. 结果

判据自始至终没变：**数值正确 _且_ 完全用 cuTile**（留任何 torch 计算算失败），
KernelBench Level 1+2 共 200 道人写的题，官方 harness 评测。头条是 **pass@1 与
pass@k 曲线**；k=4 解出数仍列出，但不再单独当「有没有进步」的判据。

| | pass@1 | pass@4 | pass@16 | 快过 `torch.compile` | 中位加速 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen3-Coder-Next 基座 | 12.9% | 23.5%（47/200） | — | 3 | 0.12x |
| **model M（少采时覆盖最宽）** | 51.6% | **75.0%（150/200）** | 未采 | 43 | 0.92x |
| model Q（pass@1 与 k=16 最好） | **54.2%** | 70.5%（141/200） | **81.5%（163/200）** | 43 | 0.94x |
| model R（修复数据） | 53.8% | 72.5%（145/200） | 未采 | 42 | 0.94x |

M 的 150 连续四轮没被超过，而那四轮的 pass@1 分别是 55.8%、52.4%、54.2%、53.8%，
全都高于 M 的 51.6%。单点把「可靠性↑、覆盖面↓」藏起来了。Q 的 163 是覆盖面最高的
读数；M 只采过 k=4，该口径没有可比数字。

按算子族（k=4 解出数）：

| 类别 | 题数 | 基座 | M |
| --- | ---: | ---: | ---: |
| conv | 98 | 5 | **75** |
| activation | 29 | 19 | 25 |
| norm | 24 | 2 | **19** |
| matmul | 15 | 11 | 13 |
| reduction | 11 | 1 | 7 |
| pool | 10 | 0 | 2 |
| other | 7 | 7 | 7 |
| loss | 6 | 2 | 2 |

卷积占基准一半，从 5 道到 75 道，是主要的增量来源。

**训练语料全部自产**：程序化生成的任务 + 模型自己的通过解，没有用任何人写的示例代码。
官方文档只在 prompt 里出现，且第八阶段之后训练用的是 2.4k token 的概念导读而非
14.9k 的完整 API 参考。

一个额外结果：**不给任何文档时仍能解出 77/200**（prompt 短 16 倍），而基座捧着完整手册
只有 47 道。模型是会 cuTile，不是在查 cuTile。

## 2. 什么起了作用，什么没有

| 干预 | 效果 |
| --- | --- |
| 拒绝采样 SFT（二、四阶段） | 有效，但受限于 prompt 太长、训得起的样本太少 |
| **撤掉训练时的文档包**（八） | **最大的单项**：样本量 7 倍、解出 51 → 84 |
| **自蒸馏**（十） | 79 → 108，且 pass@1 / pass@4 / pass@16 三个口径同时涨 |
| 第二次自蒸馏（十七） | pass@1 涨到 54.2%、k=16 到 163/200，但 k=4 解出 150 → 141 |
| **定向修复反馈**（十九） | 修复率 2.5% → **12-19%**；Level 2 纯度失败 71% → **50%**（三轮来第一次） |
| **GRPO**（十、十一、十四） | 有效，且与自蒸馏**可叠加**：108 → 127 → 134 → 150 |
| frontier 类别配额（十一） | +7 道；缺失的算子族（激活、损失）此前完全没有任务 |
| 数值 reward 分级（十二） | +10 道，且策略漂移只有原来的 1/54 |
| 纯度分级 + 链尾任务（十四） | +6 道，pass@1 首次过半 |
| 修复循环当**推理时手段**（三、七） | **撤回**：等预算下不如单纯重采（第九阶段）。注意与第十九阶段不冲突——那是把它当**数据采集器**，这个用法三、四阶段就验证过 |
| 纯度上限提到 0.3（十五） | **否定**：解出 150 → 147，且靶子反而变大 |
| 速度专项 RL（十六） | **否定**：共同题集上逐题速度比 1.000x |
| 大张量逐点激活（二十） | **否定（训前停）**：区间对了（0.614x），组内无变异（12%），没训 |
| 第二套封存题集（十八） | 尺子：770 道，激活覆盖 0 → 150 道；未开封 |

## 3. 没做到的事

**速度。** 二十轮下来正确性翻了三倍，速度基本没动：中位对 `torch.compile` 是 **0.92x**，
200 道里只有 43 道更快。如果"专家"的标准是"写出的 kernel 值得替换库实现"，
**这一条没达到**。

第十六阶段找到并修好了一个真实原因（奖励在 1.0x 以下无梯度），但那一轮训练分布选错了。
按修正后的条件重筛之后，**发现这条路用现有任务池走不通**：

| "稳定解出且比 compile 慢"的 147 道题 | |
| --- | ---: |
| matmul | **122（83%）** |
| 其余七个族合计 | 25 |
| best_speedup 中位 | **0.100x** |
| speedup < 0.5x 的 | 118/147 |

两个问题叠在一起。**一是这批题几乎全是矩阵乘对 cuBLAS**——第五阶段就量过，模型赢得了
"PyTorch 物化中间结果"，赢不了 cuBLAS/cuDNN，差十倍不是调 tile size 能补的。
**二是会在另一端重建同一个死区**：修好的速度项在 0.25x 以下钳位，而 118/147 道题就在钳位区内，
奖励在这批题上又是平的。

所以真正的结论曾是：**合成任务池里没有我们需要的区间。** 第二十阶段把这件事做完了——
造了 250 道十亿元素的逐点激活，中位 0.614x，96% 落在 0.4–1.0x，**区间对了**。
停下来的原因换成了另一件：2000 个 kernel 里 1929 个是 prompt 例子里的
`TILE_SIZE=256`，只有 12% 的题组内速度能差到 1.3x。偶尔写出 1024 / 更大的 tile，
同一道题就能到 ~1.0x，所以不是没有更快的 kernel，是策略几乎不发出它。GRPO 在
组内常数上没有优势，硬门拦住了训练。三个锚点（SELU / ELU / HardTanh）没有新读数，
仍是 ~0.556x。

**三个算子族基本没推动**：池化 2/10、损失 2/6、归约 7/11。

**Level 2 的纯度失败**：剩下的未解出题里，Level 2 有 71-75% 是"数值完全正确、但链尾留了
个 `torch.relu` 被纯度门拒掉"。奖励刻度上试过两个方向（0.0 → 0.18 有效、0.18 → 0.30 有害），
说明瓶颈不在刻度。

**测量在稀释**。dev 200 已用于十六轮选型决策；封存的合成 held-out 第十一阶段开封过一次
（结论：没有过拟合迹象，held-out 上的相对增益反而更大）；Level 3 第八阶段开封过；
Level 4 因 fp32 协议冲突不可用。**再往下走，需要先造新的封存题集。**

## 4. 方法学教训

这些比结果更值得记，因为每一条都是自我欺骗被抓住的现场。

**基线的选择是一个能骗自己的旋钮。** 十二轮里没人质疑过 eager PyTorch，而它恰好在我们最
爱宣称胜绩的融合链上最弱——那些胜绩几乎全部来自"PyTorch 物化中间结果"，
而 `torch.compile` 免费消除它。换成 inductor 之后，"中位追平 PyTorch"变成 0.92x，
而且两个模型的排序**翻转**了。选基线该问"用户真正会用什么"。

**多轮方法必须和等预算的单轮对照。** 修复循环看起来把 84 道推到 107 道，是项目最大的单项
提升。但它每题最多 16 次尝试，而对照只有 4 次。补上等预算对照后，**什么反馈都不给的重采
反而更好**（129 对 107）。第七阶段的结论因此撤回。

**一个判据用错，能把最大的靶子藏起来。** 我用 `compiled and not numerically_correct` 判定
"能跑但数值错"，报出 92%。但 `compiled` 只表示模块导入成功，而 cuTile 是首次 launch 才
JIT 编译——所有编译错误都被算成了数值错。真实的最大项是"数值正确但没过纯度门"（52%），
完全是另一回事。

**训练指标贴着天花板时不能用来排除失败模式。** 第十五阶段把纯度上限提到 0.3，训练侧纯度率
0.971 纹丝不动、pass 还在涨，我据此宣布"排除了局部最优的风险"。基准上却是丢了 9 道
"本来纯的通过解变成留 torch 尾巴"。合成任务的链太短，纯度早已到顶，那个诱惑在训练分布上
根本不存在。

**训练 reward 的逐轮读数分辨不出策略变化。** 第六阶段"reward 没动所以 RL 没用"的结论，
其测量方式本身就撑不起来：每轮从几百道 frontier 里抽 16 道，任务抽样噪声 ±0.1，
盖住了一切。第十阶段同样是平的 reward，held-out 上却多解出 19 道。**判据只能是 held-out。**

**速度必须在共同题集上逐题比。** 第十六阶段表面上 43 → 46、0.92x → 0.94x，但两个模型解出
的题不是同一批。在都解出的 136 道上逐题比，中位是 **1.000x**，120/136 变化在 ±5% 内。
涨幅全是构成效应。

**换个种子不构成 held-out。** 生成封存题集时，1481 个候选里 **1181 个（80%）与训练集逐字
重复**——形状阶梯很短，同一算子在同一形状上反复出现。必须按规范化哈希去重。

**验证器的一个种子 bug 曾让整类任务永远判失败。** 只在构造前设一次种子，参考模型建
`nn.Conv2d` 时消耗了 RNG，ModelNew 拿到不同权重——**任何自带可学习参数的任务都永远不可能
通过**。这让第二阶段误判"卷积存在冷启动"，修掉后卷积单轮就有 8.8%。

**给一个目标筛训练集，却对那个目标的分布一无所知。** 第十六阶段筛"速度 frontier"时，
用的采集跑的是不带 `--measure-time` 的验证，记录里一条计时都没有。现在
`select_frontier.py` 在这种情况下会直接报错而不是静默选空。

**硬门要在训前问，问的还得是组内变异，不只是速度带。** 第二十阶段门 1 过了（中位
0.614x），门 2 不过（12% 的题 `best/median ≥ 1.3x`）。事后看，那 12% 里每一次更快的
都是非 256 的 tile，信号是真的——但 88% 的组里八个样本全是同一个 `TILE_SIZE=256`，
advantage 是零。prompt 里的 vector-add 例子把这个数字写死了。过了速度带不等于
GRPO 有东西可学。

## 5. 工程上值得留的东西

- **官方 harness 会静默漏验**：1600 个样本只验了 593 个，其余标 `not_evaluated` 而 pass@k
  当失败——21/100 对真实的 61/100，差三倍，退出码还是正常的。
- **默认超时 300 秒是主要瓶颈**：一个挂死样本占满 5 分钟。降到 60 秒后，同样的 pass
  从"30 分钟 4 个样本"变成"25 分钟 428 个"。
- **KL 锚在 LoRA 上是免费的**：adapter 挂在已合并的监督权重上时，关掉 adapter 得到的就是
  SFT 策略本身，`disable_adapter()` 给出精确参考 logprob。此前注释里"要么抵消监督训练、
  要么再花 27.5GB"的判断是错的。没有它，策略会崩溃到 99.2% 不输出代码。
- **那个"MoE 专家全量微调"从来没必要**：前七轮每轮训 6.88B 参数，其中 4.83B 是误打误撞的
  专家全量微调。仅注意力 LoRA（137M）打平，快 2.8 倍，存档 537MB 对 26GB。
- **长任务会被机器无声回收**，连 `setsid` 出去的监督进程也会。所有循环脚本改成自读进度、
  可重复调用。

**后期最重要的一条**：连续三轮（十五的纯度上限、十六的速度、十七的自蒸馏）都是同一形态——
**pass@1 涨、k=4 解出跌**。不是三次独立失误，而是一个信号：在当前能力水平上，
**任何形式的锐化都在拿覆盖面换可靠性**。第十阶段的自蒸馏能三个口径同时涨，是因为那时
大量题目处于"偶尔做对"、蒸馏能把它们变成"稳定做对"；现在剩下的多是"很少做对"，
蒸馏强化多数派写法，把少数派里那个偶然对的解压掉了。想再涨解出数，得靠扩覆盖面的手段。

**一条贯穿全程的观察**：后期每一轮的失败都不是"方法不对"，而是**训练分布和基准分布对不上**。
类别构成（十一）、失败形态（十四，链尾激活而非独立激活）、速度区间（十六）、
发出的 tile 尺寸（二十，96% 是例子里的 256）——都是同一个形状的问题。自产语料的代价
就在这里：任务是我们造的，它的分布就是我们对困难的假设，而那个假设一直偏乐观。

## 6. 如果继续

第二十阶段把第十九阶段的靶子做完了：大张量逐点激活的速度带是对的，组内变异不够，
按硬门停了。口径也改了。还开着的口：

1. **速度若再做，先让模型写出非 256 的 tile。** 同一道题 256 → 1024 就能从 0.56x
   到 1.0x。改 prompt 例子、在概念导读里写明带宽受限不要几百万个 block、或把温度/k
   提到真能采到变异，然后用同一套硬门再筛。不许拿 level 83 这次采集直接训。
2. **扩覆盖面只剩修复循环一个真正有效的机制。** 四轮证明锐化是零和的；修复循环是唯一
   产出"模型本来写不出的解"的东西（第十九阶段 317 个）。但它单独也不够——那一轮净账 −5。
3. **第二套封存题集（770 道，level 99/88/84）已就位未开封**，含 150 道激活题。
   它的激活是 8192 量级，测不了十亿元素的速度主张，见 [tasks/HELDOUT2.md](../tasks/HELDOUT2.md)。
4. **损失族的任务空间已耗尽**（`LOSS_OPS` 只有 7 个算子），要覆盖它得先扩充损失算子面。
