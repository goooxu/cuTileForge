# 六模型 909 题：原生上下文、128K-cap、1+1+1+1

新协议，不替换旧 32K 表 A/B。六个模型各跑两组同预算 k=4：

- **control**：同一 prompt 独立采样四次；
- **adaptive**：Round 0 原始 prompt；后续三轮根据执行结果修复，或围绕当前最快
  通过解做融合、不同分解、tile/grid 改写。

通过 = 数值正确且全部计算使用 cuTile。速度只看四发通过解中最低的
`kernel_ms`。adaptive 的 p@1 是 Round 0 单发通过率，p@4 是四轮累计通过率。

## 协议

- 题目：level 60，770 latency + 139 throughput。
- Prompt：`cutile_concepts`，temperature 1.0，top-p 0.95，top-k 40。
- 目标输出 cap：131072 tokens。
- GL-E / GL 原生 context 131072，实际请求预算为
  `context - prompt - 1024`，中位约 127K。
- Next-Q / Next / G4t / Q38 原生 context 262144，请求输出上限完整 128K。
- GL-E / GL always-thinking xhigh；Q38 thinking xhigh；G4t thinking；
  Next 系列没有 thinking 开关。
- 当前 nightly 的 SM100 FlashInfer TRT-LLM BF16 MoE backend 启动时会非法访存，
  因此 Next / Next-Q 的 control 与 adaptive 两边都固定 Triton MoE backend。
- 逻辑生成预算：`909 × 4 × 6 × 2 = 43,632`。API/容器失败会按已落盘 key
  恢复，不计成新候选。

## 四轮累计 p@k

| 模型 | Round 0 | Round 1 | Round 2 | Round 3 |
| --- | ---: | ---: | ---: | ---: |
| GL-E | 73.2% | 88.3% | 91.4% | 92.4% |
| GL | 54.2% | 78.3% | 85.9% | 88.4% |
| Next-Q | 73.5% | 78.5% | 80.4% | 81.4% |
| Next | 11.7% | 22.3% | 30.7% | 36.3% |
| G4t | 54.2% | 75.4% | 80.6% | 82.9% |

弱模型从执行反馈获益最大。Q38 第一轮反馈就增加 37.4 个百分点；Next-Q 的后续
轮虽然提高单候选通过率，却集中在已解题上，p@4 反而低于四发独立 control。

## 128K 是否真的用到了

| 模型 | control completion tokens 中位 / p90 | adaptive 各轮中位范围 | 触顶情况 |
| --- | ---: | ---: | ---: |
| GL-E | 4.1K / 7.1K | 2.4K–4.0K | 仅 1–2 个样本 |
| GL | 8.6K / 14.2K | 6.7K–8.5K | 0 |
| Next-Q | 0.5K / 0.8K | 0.5K | 仅 1 个 control |
| Next | 0.8K / 2.9K | 0.7K–0.8K | control 1.1%，Round 0 1.2% |
| G4t | 4.7K / 7.9K | 3.5K–4.7K | 0 |
| Q38 | **31.8K / 55.8K** | 26.8K–32.4K | 0–0.1% |

128K 对 GL/Next/G4t 基本只是安全余量；Q38 的中位已经贴近旧 32K 上限，p90 约
56K，因此旧协议确实会截断它的大量推理。Q38 control 相对旧 32K 延迟从
27.1/47.5 提到 38.5/62.9（p@1/p@4）；adaptive 再把 p@4 推到 89.7%。

## 结论

1. **1+1+1+1 是覆盖策略，不是速度策略。** 五个模型总体速度约 1.00x，GL 还略慢。
2. **Q38 最适合这套协议。** 延迟 p@4 62.9%→89.7%，matmul 99.0%，conv 73.7%。
3. **GL 也显著受益。** 延迟 p@4 +11.3，吞吐 p@4 +7.9。
4. **Next-Q 不适合围绕单个解连续锐化。** 四发独立 control 的覆盖更宽。
5. 新结果是 native-context + 128K-cap 协议，旧表 A/B 保留，不交叉替换。
