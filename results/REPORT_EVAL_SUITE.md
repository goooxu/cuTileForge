# 独立评测集：两张协议表

同一套题（level 60：770 延迟 + 139 吞吐），一次对 `torch.compile` 计时。
通过 = 数值对且全是 cuTile。冻结采样：`cutile_concepts` + `TILE_SIZE=1024`，
k=4，温度 1.0。没有训练。

**两张表不能横比。** 表 A 是开 thinking、`max_tokens=32768`。表 B 是关
thinking、`max_tokens=8192`。旧两轨和 KernelBench 200 题头条也不要混进来。

**结论先说**

1. **表 A（32K，开 thinking）**：Q 与 M 打平（634 / 629）。Q38 366/770，洞在
   conv（23/209）。激活 130/150，接近 M。
2. **表 B（8K，关 thinking）**：Q 与 M 仍打平（634 / 632）。Q38nt 398/770，
   仍远低于两人。conv 75/209，激活 115/150。
3. 两张表里延迟和吞吐做成对都没有拉开。延迟中位 ms 和吞吐中位加速比不要横比。

# 两张表之间

不能把表 A 的中位数和表 B 折在一起。只在 Q38 自己身上看开关：

| | 表 A（think，32K） | 表 B（off，8K） |
| --- | ---: | ---: |
| 延迟 | 366/770 | 398/770 |
| 吞吐 | **121/139** | 110/139 |
| conv | 23/209 | **75/209** |
| activation | **130/150** | 115/150 |

关 thinking 换来 conv，丢掉激活和吞吐。两边都远低于同表的 M/Q（conv 174 / 177）。

32768 关 thinking 试跑（397/770，102/139）归档在 `runs/archive_q38nt_32768/`。
头条和表 B 同量级，薄尾巴不是瓶颈，不单开第三张表。那一轮也是温度 1.0 重采，
和表 B 的解出集合只重叠 285 道，不要把集合差当成上限效应。

# 这意味着什么

- 两条协议上 **Q 与 M 都打平**，延迟和吞吐都没有拉开。
- Q38 开 thinking 停在 366/770，洞在 conv。关 thinking 抬到 398，仍不是 M/Q。
- 下次新模型按 [tasks/eval/EVAL.md](../tasks/eval/EVAL.md) 的对应那张表跑，
  不要跨表填数。
