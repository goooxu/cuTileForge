# 独立评测集第一次读数：base / M / Q

**结论先说**：冻结协议（concepts + `TILE_SIZE=1024`，k=4，温度 1.0）下，

1. **正确性**账面上是 **Q ≫ M ≫ base**（649 / 425 / 103）。这个差距不能当最终结论：M 的验证被 CUDA IMA 毒过，220 道是无效失败。
2. **速度**做成对，三人打平。不要拿各自解题集合上的中位数横比。
3. **TILE**：三个模型都主要写 1024。基座仍有 3% 写 256，不是多数。

没有训练。题目是 level 60（770）+ level 61（250），合计 1020 道。

## 1. 怎么跑的

| | |
| --- | --- |
| 正确性 | level 60，770 道，不计时 |
| 速度 | level 61，250 道，对 `torch.compile` 计时 |
| 采样 | 每题 k=4，温度 1.0，`cutile_concepts` |
| 通过 | 数值对且全是 cuTile |
| 模型 | 基座 Qwen3-Coder-Next；model M；model Q |

入口是 `rl/compare_eval_suite.sh`，每个模型走一遍 `rl/run_eval_suite.sh`。12240 个样本，外加 3000 道速度轨计时。

## 2. 正确性：账面分不能当最终结论

| | 解出（k=4） | pass@1 | pass@4 |
| --- | ---: | ---: | ---: |
| base | 103/770 | 4.9% | 13.4% |
| M | 425/770 | 44.1% | 55.2% |
| **Q** | **649/770** | **72.1%** | **84.3%** |

账面上 Q 的 pass@4 比 M 多 224 道。**不能这么读。**

M 的 3080 个样本里有 948 个报 `illegal memory access`。前 2058 个完成的样本里 1351 个通过、零 IMA，机器当时是好的。第一发是 M 自己的 `567:3`（0.291 秒）：一道 adaptive pool，`grid = (batch, 65536, 1)`，超过 CUDA 网格上限。另外三个样本分别是 `Grid[1] too big` 和 `TileTypeError`，没有 IMA。

后面 947 个 IMA 全是 0.001 秒——验证器在 IMA 之后不 `cudaDeviceReset`，同一张卡上的 worker 接着跑，kernel 没执行。OOM 算 inconclusive，IMA 却记成失败。这 947 个不是外部作业，也不是那 947 个 kernel 写爆了。

Q 在同一道 567 上也写过 `grid=65536`，被 `ValueError` 拦住，没有把设备毒死。Q 的验证里 IMA 是 0。base 没 IMA，但有一次同类传染（`illegal instruction`，1140 个，几乎全是 0.001 秒）。

| | 题数 | M | Q |
| --- | ---: | ---: | ---: |
| 全量（含无效失败） | 770 | 425 | 649 |
| M 四个样本全是 IMA（无效） | 220 | 0 | 194 |
| M 一次 IMA 都没有（能打分） | 520 | **424** | **438** |

能打分的 520 道上 Q 只多 14 道（81.5% 对 84.2%）。按出处：

| 出处 | 能打分 | M | Q |
| --- | ---: | ---: | ---: |
| 99（程序化） | 351 | 283 | 297 |
| 88（Q 自撰图，已变异） | 169 | 141 | 141 |
| 84（激活 / 损失 / 归约） | 0 | — | — |

88 上两人打平，并不是 Q 碰过自己出的题。84 的 120 道对 M 全部无效，Q 解出 107 不能拿来比。M 在 source 99 的激活题上是 28/34，速度轨（同样是激活）是 240/250，不是不会写激活。

真差距要等把 M 的 220 道无效题单独重验。现在只能说：Q 略强，不是完胜。

## 3. 速度：做成对，打平

| | 解出（k=4） | pass@1 | pass@4 | 各自解题集上的中位加速 |
| --- | ---: | ---: | ---: | ---: |
| base | 105/250 | 16.7% | 42.0% | 1.062x |
| M | 240/250 | 87.6% | 96.0% | 1.084x |
| Q | 241/250 | 87.0% | 96.4% | 1.083x |

最后一列不能横比：base 只解出 105 道，M / Q 解出 240。协议只认共同题上的成对比（阈值 1.05x）：

| | 共同题 | 中位比 | 更快 | 更慢 |
| --- | ---: | ---: | ---: | ---: |
| M vs base | 100 | 1.004x | 16 | 4 |
| Q vs base | 100 | 1.002x | 16 | 7 |
| Q vs M | 240 | 0.997x | 9 | 7 |

M 和 Q 对 compile 都在 1.08x 附近，彼此 0.997x。基座在它能解的那 100 道上也是同一档。没有模型把另外一个拉开。

## 4. 基座也会写 1024

速度轨 1000 个 kernel 里写出的 tile：

| | 1024 | 256 | 其他 |
| --- | ---: | ---: | ---: |
| base | 964 | 30 | 4 |
| M | 978 | 1 | 15 |
| Q | 930 | 0 | 39 |

基座不再默认 256（30/1000 = 3%）。Q 一个 256 都没写，但有 39 个写成整行量级的大 tile，还有 31 个解析不到 TILE 常量。M 最听话：978 个 1024。

## 5. 这意味着什么

- 正确性账面上 Q 远超 M，去掉 IMA 毒死的题之后只多 14 道。84 那 120 道还没能公平比。
- **速度没有拉开。** 三人对 compile 打平；测的是十亿元素逐点，TILE=1024 之后都在 1.0x 附近。
