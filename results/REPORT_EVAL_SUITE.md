# 独立评测集：两张协议表

同一套题（level 60：770 延迟 + 139 吞吐），一次对 `torch.compile` 计时。
通过 = 数值对且全是 cuTile。冻结采样：`cutile_concepts` + `TILE_SIZE=1024`，
k=4，温度 1.0。没有训练。

**两张表不能横比。** 表 A 是开 thinking、`max_tokens=32768`。表 B 是关
thinking、`max_tokens=8192`。旧两轨和 KernelBench 200 题头条也不要混进来。

**表内名称**（脚本和 `runs/` 目录仍用短 tag）：

| 表内 | tag | 是什么 |
| --- | --- | --- |
| Next | `base` | Qwen3-Coder-Next，未在本项目训练 |
| Next-M | `M` | 拒绝采样 SFT → 丢掉长文档 → 自蒸馏 → GRPO |
| Next-Q | `Q` | 在 Next-M 的通过解上第二次自蒸馏 |
| Q38 / Q38nt | `Q38` / `Q38nt` | Qwen3.8-27B，开 / 关 thinking |
| G4 / G4t | `G4` / `G4t` | Gemma-4-31B-it，关 / 开 thinking |
| GL | `GL` | Muse Glimmer 30B，未在本项目训练 |
| GL-A | `GLA` | 在 GL 上拒绝采样 SFT（保留它自己的推理轨迹），第一轮 |
| GL-B | `GLB` | 在 GL-A 自己的通过解上自蒸馏 |
| GL-C | `GLC` | 在 GL-B 上再做一轮 SFT，补回 activation / elementwise |
| GL-E | `GLE` | 在 GL-C 上混训：第二次自蒸馏 + level 80 速度切片 |

Glimmer 线的 checkpoint 从字母 A 开始排，和 Next 线当年一样。别把 GL-A 读成
Next-M 的对应物：Next-M 是第 9 次改权重之后的那个 checkpoint，GL-A 只训了一轮。
GL-B 对应的是 Next 第十阶段那种自蒸馏，不是 Next-Q 那种第二轮锐化。GL-C 是对着
GL-B 掉下去的那 139 道 twin 做的恢复，不是盲目再蒸馏一轮。GL-E 是对着 GL-C 再做
一轮混训；表 A 只能看相对 GL-C 动了没有，不能拆开是蒸馏还是速度池。GL-D 的
GRPO 低于 GL-C，不作发表线。

**结论先说**

1. **表 A（32K，开 thinking）**：GL-E **695/770**，覆盖和 pass@4（90.3%）最高；
   pass@1 **69.8%**，超过 Next-Q 的 69.4%。吞吐 **132/139**，pass@1 **84.7%**。
   GL-C 680 / 66.8% / 88.3%，吞吐 131/139。GL-B 668，Next-Q 634，GL-A 619，
   GL 580，G4t 569，Q38 366。
2. **配方继续走得通**：GL → 580 → GL-A 619 → GL-B 668 → GL-C 680 → GL-E **695**。
   相对 GL-C：conv 182→188，pool 59→65，matmul 82→85。速度按 `kernel_ms` 没动
   （GLE vs GLC 中位 1.008x，见 A.2）。compile 加速比那一列不能用。
3. **表 B（8K，关 thinking）**：Next-Q 与 Next-M 仍打平（634 / 632）。Q38nt 398/770。
   G4（官方默认关 thinking）354/770，低于 Q38nt，远低于 Next-M / Next-Q。conv 57/209，
   激活 111/150。loss 5/5。
4. 两张表里延迟和吞吐做成对都没有拉开。延迟中位 ms 和吞吐中位加速比不要横比。
   G4 与 G4t 不能横比。

# 这意味着什么

- 两条协议上 **Next-Q 与 Next-M 都打平**，延迟和吞吐都没有拉开。
- **配方不绑基座，而且对着缺口再训一轮也打得中。** GL → 580 → GL-A 619 → GL-B 668
  → GL-C 680/770 → GL-E **695/770**。GL-E 相对 GL-C：延迟 680→695，pass@1
  66.8%→**69.8%**（超过 Next-Q 的 69.4%），pass@4 88.3%→90.3%。吞吐 131→132。
  表 A 不能拆开是蒸馏还是速度池。GL-D 的 GRPO 低于 GL-C，不作发表线。
- **速度还是没动。** 诚实口径是 `kernel_ms`：GL-E vs GL-C 中位 1.008x，
  GL-C vs GL-B 中位 1.015x。compile 加速比被参考解墙钟污染，不引用。
- Q38 开 thinking 停在 366/770，洞在 conv。关 thinking 抬到 398，仍不是 Next-M / Next-Q。
- G4t 进表 A：569/770，紧挨 GL（580）。conv 119，matmul **73**，norm **85**。
- G4 只进表 B：354/770，低于 Q38nt，洞在 conv / matmul。不要和 G4t 横比。
