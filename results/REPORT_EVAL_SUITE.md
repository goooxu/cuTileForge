# 独立评测集第一次读数：base / M / Q

**结论先说**：冻结协议（concepts + TILE_SIZE=1024，k=4，温度 1.0）下，

1. **正确性**排序是 **Q > M >> base**（649 / 630 / 180）。Q 略强，不是完胜。
2. **速度**做成对，三人打平。不要拿各自解题集合上的中位数横比。
3. **TILE**：三个模型都主要写 1024。基座仍有 3% 写 256，不是多数。

第一次验证把 CUDA 上下文腐坏当成 exec 失败，M 和 base 的正确性被压低了。修好验证器之后只重验了正确性轨（kernel 没重采，速度轨当时是干净的）。

没有训练。题目是 level 60（770）+ level 61（250），合计 1020 道。

## 1. 怎么跑的

| | |
| --- | --- |
| 正确性 | level 60，770 道，不计时 |
| 速度 | level 61，250 道，对 `torch.compile` 计时 |
| 采样 | 每题 k=4，温度 1.0，`cutile_concepts` |
| 通过 | 数值对且全是 cuTile |
| 模型 | 基座 Qwen3-Coder-Next；model M；model Q |

入口是 `rl/compare_eval_suite.sh`。正确性重验是 `rl/reverify_eval_suite.sh`。

## 2. 正确性：Q 略强于 M

| | 解出（k=4） | pass@1 | pass@4 |
| --- | ---: | ---: | ---: |
| base | 180/770 | 9.0% | 23.4% |
| M | 630/770 | 67.0% | 81.8% |
| Q | **649/770** | **72.1%** | **84.3%** |

Q 比 M 多 19 道，pass@1 高 5.1 个百分点。按出处：

| 出处 | 题数 | base | M | Q |
| --- | ---: | ---: | ---: | ---: |
| 99（程序化，全类别） | 400 | 93 | 320 | 335 |
| 88（Q 自撰图，已变异） | 250 | 38 | 203 | 207 |
| 84（激活 / 损失 / 归约） | 120 | 49 | **107** | **107** |

84 上两人打平。88 上 Q 只多 4 道，不是「碰过自己出的题」。

按族（k=4 解出）：

| 族 | 题数 | base | M | Q |
| --- | ---: | ---: | ---: | ---: |
| conv | 209 | 22 | 174 | 178 |
| activation | 150 | 63 | **134** | **134** |
| elementwise | 105 | 40 | 96 | 98 |
| matmul | 102 | 19 | 67 | 72 |
| norm | 102 | 23 | 81 | 85 |
| pool | 75 | 4 | 59 | 64 |
| reduction | 22 | 6 | 16 | 15 |
| loss | 5 | 3 | 3 | 3 |

激活族也是打平。Q 的余量散在卷积、matmul、norm、pool 上，每族几道。

## 3. 第一次验证错在哪

一道坏 kernel 会把 GPU 留在 sticky error 里。验证器接着用同一张卡跑后面的题，1 毫秒就报 `illegal memory access` / `illegal instruction`，却记成 exec 失败。OOM 本来就是 inconclusive。

M 的种子是 `567:3`（adaptive pool，grid 第二维 65536）。base 是一次 `illegal instruction`。Q 没把设备毒死，所以第一次的 649 没变。

| | 第一次（污染） | 重验 |
| --- | ---: | ---: |
| base | 103 | **180** |
| M | 425 | **630** |
| Q | 649 | 649 |

验证器现在把这类错误标成 `cuda_poison`，杀掉全部 worker，在独立进程里 `cudaDeviceReset`，再重试。还在 IMA 的 kernel 记 exec；1 毫秒的传染会在干净上下文里重跑。`rl/reverify_eval_suite.sh` 只重验已有 kernel。

## 4. 速度：做成对，打平

速度轨第一次就是干净的，没有重计时。

| | 解出（k=4） | pass@1 | pass@4 | 各自解题集上的中位加速 |
| --- | ---: | ---: | ---: | ---: |
| base | 105/250 | 16.7% | 42.0% | 1.062x |
| M | 240/250 | 87.6% | 96.0% | 1.084x |
| Q | 241/250 | 87.0% | 96.4% | 1.083x |

最后一列不能横比。协议只认共同题上的成对比（阈值 1.05x）：

| | 共同题 | 中位比 | 更快 | 更慢 |
| --- | ---: | ---: | ---: | ---: |
| M vs base | 100 | 1.004x | 16 | 4 |
| Q vs base | 100 | 1.002x | 16 | 7 |
| Q vs M | 240 | 0.997x | 9 | 7 |

## 5. 基座也会写 1024

速度轨 1000 个 kernel 里写出的 tile：

| | 1024 | 256 | 其他 |
| --- | ---: | ---: | ---: |
| base | 964 | 30 | 4 |
| M | 978 | 1 | 15 |
| Q | 930 | 0 | 39 |

基座不再默认 256（30/1000 = 3%）。Q 一个 256 都没写，但有 39 个写成整行量级的大 tile。M 最听话：978 个 1024。

## 6. 这意味着什么

- 这套尺子上 **正确性 Q 略强于 M**（649 对 630），激活和 source 84 打平。
- **速度没有拉开。** 三人对 compile 打平。
